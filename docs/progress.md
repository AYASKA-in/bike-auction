## Day 2 (12 Oct 2026): authentication and roles, complete locally; deploy pending

**Done**

- Better Auth 1.7.7 on D1 (native D1 dialect), password hashing delegated to `PasswordHasherDO`
  (Better Auth's own scrypt; ADR 002). Session cookie `ba.session_token`: HttpOnly, SameSite=Lax,
  `__Secure-` + Secure on HTTPS, 7-day expiry, server-side revocation on sign-out.
- Migration `0002_auth.sql`: Better Auth tables (generated by the library, `role` hardened with CHECK),
  `login_throttle`, `security_events`. Drift test guards it.
- Roles: server-only `role` field (`input:false`), `loadSession` / `requireUser` / `requireAdmin`.
  Admin sub-app with the guard at router level; `/api/v1/me`, `/api/v1/admin/overview`, `/api/v1/admin/security-events`.
- Bot and abuse protection: Turnstile via Better Auth's captcha plugin (fail-closed outside development);
  edge Rate Limiting binding (20/min/IP on credential endpoints); per-account exponential lockout keyed by
  HMAC(email) (identical for unknown accounts: no enumeration); password deny-list (common, name, email).
- All auth errors normalised to RFC 9457 problem+json (new codes: INVALID_CREDENTIALS, ACCOUNT_EXISTS,
  WEAK_PASSWORD, CAPTCHA_FAILED). Security events stored with HMACed identifiers (no raw emails or IPs).
- Demo accounts: idempotent operator endpoint `POST /api/v1/internal/seed` (bearer SEED_TOKEN, constant-time
  compare; disabled when unset) + `apps/worker/scripts/seed.mjs`.
- Web: sign-in and registration (React Hook Form + shared Zod schemas, show/hide password, accessible errors,
  Turnstile widget with single-use reset), demo-account picker, session-aware header, admin "Auction desk"
  page with route guard; `/api/v1/config` delivers runtime config (one build for all environments).
- Config is production-safe by default; local overrides come from `.dev.vars` (auto-created by `pnpm dev`).
- `scripts/deploy.mjs` (idempotent one-command deploy) and `scripts/auth-gate.mjs` (20× check).
